Posted on 2026-09-22 In ctf Disqus:

Challenge

音频与图片两份附件，题面说房间比消息本身更吵。难点在于载波藏在声道差里，且要先用 CRC 把三遍传输的位定下来，才能拿到读图所需的种子。

The room is louder than the message. Listen to the difference.

房间比消息本身更吵。听差分。

Solution

附件 crossfeed-player.zip 含 crossfeed.wav（16 kHz 立体声）与 embers.png。

Step 1：载波在声道差 L − R 里：用 1375 Hz 复载波下变频，对每个 640 样本窗口取 Y[end]-Y[start]，实部符号即 bit。1375 Hz × 640/16000 = 55 个整周期/bit，所以窗口相位与位定时无关。

Step 2：用 24-bit 前导码 A5A5A5 在全部 640 个相位偏移上搜索，命中三个起点 bit 8 / 320 / 632（极性取反），间距 312 bit = 24(前导) + 256(32 个 hex 字符) + 32(CRC32)。

Step 3：三遍逐 bit 多数票得到 32 个 hex 字符，其 CRC32 与传输的 CRC 字段一致：

Step 4：按 idx = BE32(SHA256(seed || BE32(counter))[:4]) % N（N = 384×384，命中的位置跳过、counter 不重置）读 embers.png 蓝通道 LSB，位流 MSB-first 组字节，得到长度字段 + payload + CRC32，校验通过。

CodeShell.kr - Errata

Posted on 2026-09-22 In ctf Disqus:

Challenge

三条 lane 各 128 个点，其中恰好 32 个 y 值被篡改。这是标准 Reed–Solomon 纠错，难度在于要把「恰好 96/128 成立」这条自洽性当成验证依据。

Recover the message

恢复消息。

Solution

附件 errata-player.zip 含 rules.md、samples.csv（384 行 = 3 lane × 128 点）、cipher.bin（30 字节）。

Step 1：规格是 GF(257) 上三条 lane，每条 128 个点、真实数据为 degree ≤ 15 的多项式，其中恰好 32 个 y 值被篡改（errata）。这是标准 Reed–Solomon 纠错问题，用 Berlekamp–Welch 求解（n=128, k=16, e=32，需 128 ≥ 16 + 2·32 = 80，可行）。

Step 2：三条 lane 的拟合曲线恰好在 96/128 点上成立（96 = 128 − 32），与规则里的 "Exactly 32 altered y values per lane" 完全一致，且多项式除法余数为 0：

Step 3：按升序系数、BE16、逐 lane 拼接得 T（96 字节），K = SHA256("ERRATA/DEVIL/V1" || T)，S = SHA256(K||BE32(0)) || SHA256(K||BE32(1)) || ...，flag = cipher.bin XOR S[:30]。

CodeShell.kr - Fractured Loom

Posted on 2026-09-22 In ctf Disqus:

Challenge

8192 条 24 字节指令、7 个 op 的织机 VM，状态 512 位。难点在于 opcode 有 3 位藏在操作数里，且字节代换的移位量只有逐指令对齐才能确认。

Unweave the loom

拆开织机。

Solution

readme.txt：输入恰好 64 个十六进制字符；只有当八个 64-bit lane 到达隐藏终态时 才接受；提交 CodeShell{SHA256(raw_input_bytes)}。

Step 1：64 个字符按两字符一组（高位 nibble 在前）解析成 32 字节。初始状态是 8 个 64-bit lane，每个 4 字节大端 dword 复制成两半再与一张表异或：

Step 2：.rodata+0x80 是一个 0x30000 字节的 "loom" 程序 = 8192 条 24 字节指令， 布局 [op, A, B, C, imm32, Q1(8), Q2(8)]。真实 opcode = op ^ ((Q1 >> 17) & 7) （3 bit 藏在 Q1 里），经 7 项跳转表分发：

接受条件是最终 64 字节状态等于 .rodata+0x40 的常量。

Step 3：七个 op 全是 512 位状态上的双射，所以从终态倒着跑即得初态。 op3 的逆需要 Q2 在 mod 2^64 下的乘法逆元（Q2 全为奇数，可逆）。

这里有一个只有逐指令对齐才能发现的坑：op5 的移位量是 (Q1 >> 3) & 0x38， 取的是 Q1 的第 6–8 位，而不是直觉上的 ((Q1 >> 3) & 7) * 8（第 3–5 位）。 写成后者时只有 8 个字节位置中的一部分会错，肉眼很难看出来。把 GDB 单步的 连续 59 条指令与 Python 正向模型逐一比对后，才定位到第 5 条指令的差异。

八个 lane 反推后都满足"同一 dword 复制成两半"的约束，说明解自洽。

CodeShell.kr - Glass Register

Posted on 2026-09-22 In ctf Disqus:

Challenge

同模板第三题，多了一条链式累加，而且最终判据是反相的。难度在于只匹配期望表会在特定情况下误判。

A register mixer with no useful output until the state is reconstructed.

一台寄存器混合器，在状态被重建前没有任何有用输出。

Solution

Step 1：与 Opcode Picnic 同一生成器模板，常数不同：strlen == 33，.rodata @ 0x2020 是 33 字节逆序索引表（32..0），0x2060 是 33 字节期望累加器低字节。

与 01 的差异：内层 4 → 11 轮；种子 0x4a9a4ce9；shr edx,cl 的 cl = (edi&3)*8；rol dl,cl 的 cl = ((edi+i) mod 7)+1（用 magic 0x24924925 实现除 7）；r8/r13 每外层轮清零；r10 = i*0x45d9f3b。

Step 2：本题独有：外层每轮之后有一条链式累加 r14 = rol32(r14 ^ i*0x9e37 ^ acc_byte, ((i+3) mod 29)+1)（除 29 用 magic 0x469ee58469ee5847），最终判据是 cmp r15d,r13d 后 je rejected，反相，必须 r15d != r13d 才 accepted。只匹配期望表而忽略这条，会在 r15d == r13d 时误判。

Step 3：33 轮暴力全部唯一命中（无 0 解、无多解），链式判据对候选成立。寄存器模型用 GDB 单步校验：33 轮逐轮 sil 与模型完全一致，最终 r15d=62、r13d=4194943236 两边同值；随机输入对照同样一致。

Solution

Step 1：64 个十六进制字符解析成 8 个小端 dword（state = (state << 4) | nibble， 所以第一个字符是最高位 nibble）。.rodata+0x20 是一个 0x8000 字节的字节码程序 = 4096 条 8 字节指令，每条 [op, A, B, C, imm32]。一个 LCG（种子 0x0d5203ce、 乘数 0x19660d、增量 0x3c6ef35f）每条指令供 2 bit，真实 opcode = op ^ (lcg & 3)：

r8 每条指令都从 imm 字段重载，不跨指令传递，这一点容易读错。

Step 2：两个反直觉之处。其一，终态不是全零：最终检查把 state 与 .rodata+0xa020 的 32 字节常量异或后整体取或，只有结果为 0 才通过：

其二，.rodata+4 是 "no"、.rodata+7 是 "yes"，而 cmovne rdi,rax 在非零时取 0x2004，所以全零状态会被拒绝（实测输入 64 个 0 得到 no）。

Step 3：四个 op 全是 256 位状态上的双射，所以不搜索，从目标态倒着跑即得初态：

正向模型先用 GDB 对齐（全零输入下 Python 与二进制在最终检查点处的 8 个 dword 完全一致），反向后再正向跑一遍确认回到目标态。
